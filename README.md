# rviz2_cinematographer-release

This is the [bloom](https://github.com/ros-infrastructure/bloom) release repository for
[hakuturu583/rviz_cinematographer](https://github.com/hakuturu583/rviz_cinematographer).

Released packages:

- `rviz2_cinematographer_msgs`
- `rviz2_cinematographer_view_controller`
- `rviz2_cinematographer_video_recorder`
- `rviz2_cinematographer_gui`

## Tracks

`tracks.yaml` defines one track per ROS 2 distribution, all releasing the `master` branch of the
upstream repository at the tag matching the package version (`:{version}`, e.g. `0.2.0`):

| Track | ROS distro |
|---|---|
| `humble` | Humble Hawksbill |
| `jazzy` | Jazzy Jalisco |
| `kilted` | Kilted Kaiju |
| `lyrical` | Lyrical Luth |
| `rolling` | Rolling Ridley |

## Releasing a new version

1. In the upstream repository, bump the versions and changelogs and tag the release:

   ```
   catkin_generate_changelog   # then edit the CHANGELOG.rst files
   catkin_prepare_release      # bumps package.xml, commits and pushes the tag
   ```

2. Run the **bloom-release** workflow (Actions tab -> bloom-release -> Run workflow) with the
   tracks to release. It runs `git-bloom-release <track>` for each track and pushes the generated
   branches and tags to this repository.

   Alternatively, run bloom locally:

   ```
   for distro in humble jazzy kilted lyrical rolling; do
     bloom-release --rosdistro ${distro} --track ${distro} rviz2_cinematographer
   done
   ```

3. Open a pull request against [ros/rosdistro](https://github.com/ros/rosdistro) adding or bumping
   the `rviz2_cinematographer` entry in `<distro>/distribution.yaml` (the workflow does not do this;
   local `bloom-release` does).

Everything except `master` (the `upstream`, `release/*`, `debian/*` and `rpm/*` branches and
their tags) is generated by bloom; do not edit those branches by hand.
